# Quality

The Stage 1 target is local use on Linux desktop. Windows and macOS are deferred; distribution, supported OS versions and architectures, release guarantees, human accessibility acceptance and performance targets are Pending. A successful Linux check does not imply support on another platform.

For the implemented terminal experience, keyboard operation must not depend on color alone; the smallest supported view is 55 columns by 19 rows; too-small resizing preserves application state; the selected workbook path remains accessible, including through the scrollable overflow view; and normal exit or recoverable failure restores terminal settings. These behaviors and failure cases are specified in [interactive analysis](interactive-strategies.md) and [terminal experience](experience.md), with Linux evidence and limits in [PROOF](../proof/interactive-strategies.md).

Numerical outputs are descriptive. Their sample spaces, eligible populations, units, missing-value rules, precision, rounding and boundaries are specified in [numerical contracts](numerical-contracts.md) and [series statistics](series-statistics.md). Integer and combinatorial results should remain exact where feasible; unavailable values must not be presented as zero. Independent reference cases and boundary checks provide evidence for implementation correctness but do not establish predictive value.

Local input validation, snapshot consistency, size bounds and freshness failure behavior are specified in [PROJECT](../project/interactive-strategies.md). Data processing is local; the separate development updater is not a runtime application dependency. User value, usability, other-platform behavior, exhaustive malformed-workbook compatibility and out-of-sample predictive performance remain unverified, as recorded in [validation](../proof/validation.md).
