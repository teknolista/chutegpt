# Interactive analysis design

Design for IA-01–IA-07 and catalog S01–S22 in [PRODUCT](../product/interactive-strategies.md). The current binary uses Ratatui and Crossterm for the terminal and Calamine for XLSX; exact selected dependencies and Linux evidence are recorded below. MSRV and actual Windows/macOS support remain unverified.

Proposed separation: source adapter -> validated immutable draw snapshot -> independently callable pure strategy functions -> typed results -> terminal presentation. Snapshot includes contest number, date, seven distinct numbers, month and optional prize fields, source path, hash and freshness provenance. Sorting must be chronological, with duplicate, missing, malformed and inconsistent contest numbers detected explicitly. Support existing month representations numeric 1–12 and Portuguese names including HTML entity variants. Freeze bytes and hash per analysis to avoid changing results during updates.

Do not use unsafe Rust in project code unless specifically justified and reviewed; preserve terminal state by scoped cleanup. Propagate errors with actionable context. Worker and UI communication should bound memory, allow progress and cancellation and avoid sharing mutable analytical state. No network requests are required to process the local snapshot. Release artifacts and OS-specific terminal support must be checked on actual targets.

Owner decision: use a user data directory by default, allow a user-provided workbook path, and warn when no matching successful update was recorded on the local day or freshness is unknown. The existing updater writes to the repository docs directory; the development invocation must pass that path explicitly or configure the same destination. Do not silently treat metadata for a different file as valid. Required and optional workbook columns are specified below; cross-platform path resolution is specified below. S01–S22 formulas and unknowns belong to PRODUCT. No performance target or platform version invented. Compatibility with the existing Python updater and workbook metadata must be validated at integration.

## Workbook path and freshness contract (IA-01, IA-02)

Technical choice within the owner's delegated path decision; implemented in the development binary and with Linux as the current target; other platform paths below are historical design notes and require a future scope decision and verification. `--planilha PATH` selects the workbook explicitly, with relative paths resolved against the process working directory. Without the option, append `ChuteGPT/Dia de Sorte-atual.xlsx` to: Linux `$XDG_DATA_HOME` when it is absolute and nonempty, otherwise `$HOME/.local/share`; macOS `$HOME/Library/Application Support`; Windows `%LOCALAPPDATA%`. If the applicable base directory cannot be determined, explain the error and ask for `--planilha`; do not silently select a different workbook. Do not create or download a workbook on launch.

For any selected workbook, look for `.dia-de-sorte-atualizacao.json` in its parent directory. The existing updater writes exactly this name next to `docs/Dia de Sorte-atual.xlsx`. The selected workbook's frozen bytes determine the SHA-256 and parsed latest contest. A trustworthy version-2 record must be a JSON object with `version` = 2, `source` exactly `https://servicebus3.caixa.gov.br/portaldeloterias/api/resultados/download?modalidade=Dia%20de%20Sorte`, a matching lowercase SHA-256 in `sha256`, a positive integer `latest` matching the parsed snapshot, and a valid ISO calendar `date` no later than the local current date. Same local date means checked today; an earlier valid date means stale; missing, unreadable, malformed, mismatched, future-dated or unsupported records mean freshness unknown. `downloaded_at` is informational and does not override `date`. Verify using the frozen bytes, not a second changing file read. The hash and source bind metadata to contents but do not authenticate the file independently. Regardless of metadata, validate the workbook before use; a same-day check does not prove a later draw was published.

The updater only writes in the repository; it does not install or synchronize files to a user's data directory. For installed use the user supplies the official workbook at the default location or via `--planilha`. To preserve updater provenance when copying, copy the workbook and its sidecar to the same destination directory; mismatched bytes or incomplete copies must produce unknown freshness, not a false current state. An independent download or workbook without a matching sidecar is usable after the unknown-freshness warning and explicit confirmation.

Shared category-series computation and its applicability are specified in [PRODUCT](../product/series-statistics.md). Keep the statistics engine independent of terminal state, reuse typed availability/error states and preserve missing observation positions. The UI must remain responsive and cancellable while processing numerous series; completion and resource behavior need real checks. Binary64 results near bin boundaries require platform-specific validation.

## Workbook input contract

For the current official format, use the first worksheet and identify the header row by the exact required column names `Concurso`, `Data Sorteio`, `Bola1` through `Bola7`, and `Mês da Sorte`; reject missing or duplicated required names and formula/error cells in required fields. Skip wholly empty trailing rows, but reject incomplete nonempty draw rows. Contest is a positive integer; date is a valid Brazilian `DD/MM/YYYY` text date or a genuine Excel date cell; balls are seven distinct integers 1..31, normalized to increasing order; month is a whole integer 1..12 or Portuguese month name after trimming, case normalization and HTML entity decoding, including março/marco. Sort by contest, require unique and contiguous IDs from 1 through the maximum, and nondecreasing valid dates in contest order; reject duplicate IDs, gaps, invalid values or dates and describe the problem. Never construct partial analysis results after invalid required data. These constraints preserve the updater's full historical snapshot expectation while accepting unordered ball cells after normalization.

Recognize optional paired winner count and rate columns from the current Caixa header for 7, 6, 5, 4 hits and lucky month. Winner counts are nonnegative whole numbers; rates are nonnegative Brazilian currency text (including `R$` and thousands separators) or finite spreadsheet numbers exactly representable to cents. Missing, malformed, negative or excess-precision optional cells become unavailable with field-specific warnings and counts, not zero; the affected calculations use their own available denominators. Unexpected extra columns do not become required. Invalid header or absent optional columns must not be interpreted positionally as another tier. The workbook bytes and unzip resource use must be bounded before expensive parsing; use the existing updater's 15 MiB compressed and 50 MiB total uncompressed limits as initial limits, reject oversized, corrupt, duplicated ZIP entries, decompression errors and unsafe archive paths without extracting files. The parser must not execute workbook content. Show filename and contextual error without exposing unnecessary file contents. Actual workbook formats and local date handling are validated in task 2.2; these are planned behaviors.


## Selected dependencies (implementation prerequisite)

On 2026-11-16, select exact direct versions Ratatui 0.30.2 with Crossterm backend 0.29.0, Calamine 0.38.0 with date support, Chrono 0.4.42, serde_json 1.0.145, sha2 0.10.9 and zip 9.0.0 with deflate. Package information and publishers were checked against crates.io; direct versions are in Cargo.toml and resolved transitive versions in Cargo.lock. These provide terminal UI/events, local XLSX/date parsing, sidecar JSON and SHA-256 validation, and bounded ZIP inspection respectively. Linux `cargo check` compiled the selected set on rustc 1.100.0; this does not establish Windows/macOS compatibility or complete runtime behavior. The initial project package reports unused dependencies until their tasks are implemented.

Task 2.2 implementation exists in `src/data.rs`: path resolution, bounded XLSX/ZIP read, immutable bytes and SHA-256, required-field validation, optional prize availability counts and version-2 freshness classification. The loader returns data or contextual errors without producing partial results; subsequent tasks integrated it with the CLI and terminal. See PROOF for actual checks and platform limits.

Task 2.3 implementations are in `src/analysis.rs`: independent parity, repeat, strictly-prior recurrence, adjacency, longest run, sum and digital-root histograms retain per-draw observations, eligible/excluded counts and cooperative progress/cancellation. They accept validated snapshot draws. UI integration and shared category-series detail remain separate tasks.

Task 2.4 implementations are in `src/advanced.rs`: multi-metric dispersion, gap analysis, decade and last-digit groups, matrix maxima and distance. Results retain per-draw values, exact grouped counts and two-decimal histogram keys. They use validated draws and cooperative cancellation. Shared-series detail and terminal presentation remain separate tasks.

Task 2.5 implementations are in `src/history.rs`: independent nonoverlapping 27- and 31-number cycle trackers with unfinished tails; exact 1-based lexicographic ordinals and banded deltas preserving repeated outcomes; and counts/delays for individual numbers and months. Calculations accept validated draws and support cooperative cancellation. Visualization and shared-series details were added by tasks 3.3 and 3.4; see PROOF.

Task 2.6 implementations are in `src/historical.rs`: prior-only frequency and absence ranking/periodicity with inclusive ties, coverage-gated frequency-delay dispersion, rounded mean of roots, weekday tier accumulators and month/principal-prize event series. Optional prize absence, censored waits and checked monetary totals remain explicit. Histograms and terminal presentation are assembled by later tasks.

Task 2.8 implements the shared series/statistics library in `src/series.rs`, including category observation conversion, explicit unavailable measures, zero waits, unknown intervals, censored tails and cooperative cancellation. Attaching category detail to each applicable result and rendering it are still terminal integration work.

Task 3.1 integrated `src/main.rs`, `src/ui.rs` and `src/presentation.rs`: the CLI resolves the workbook path, the Ratatui menu launches local snapshot loading, and stale/unknown/error screens retain an explicit return/continue choice. Current behavior and check boundaries are in PROOF; cross-platform validation remains open.

Task 3.2 uses a bounded message channel and capped progress updates per frame, cooperative cancellation, an animated indicator when a total is unknown, and a scoped terminal guard that restores terminal settings. Loading and computation run outside the UI thread; a cancelled loading worker may finish its bounded read in the background after the UI returns to the menu. Further real-platform interruption testing remains an integration/release check.

Task 3.3 uses Ratatui bar charts and scrollable textual values in `src/ui.rs`, backed by sections in `src/presentation.rs`. Category selection opens shared-series summaries; section/scroll and selected category persist across terminal resizing. Aggregated non-sequential gap samples explicitly do not offer a category event series.
